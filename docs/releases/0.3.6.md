# LintabOS 0.3.6 (pre-release)

A real user's tablet had no partition LinWinMod could recognise automatically.

## The gap

`disks.find_windows()` (what `windows_partitions()` relies on) needs a `\Windows\System32` folder found via a real
mount, or to be the biggest Microsoft-data partition on a disk whose ESP has a Windows boot manager. An unusual
layout, or a secondary NTFS data partition without a detectable `System32`, satisfies neither — and so never showed
up in LinWinMod at all, with no way to tell it "no, use this one."

## The fix

LinWinMod's Files tab now also lists **every** NTFS partition on the tablet (`list_ntfs_partitions()`), in a
dropdown with a "Use this partition" button — regardless of whether it looks like "the" Windows install. The same
Fast-Startup/dirty safety check (`lintab-windows-files enable --read-write`'s own gate) still applies before
anything is mounted read-write, and switching which partition is set up no longer leaves a stale mount of the
previous one behind.

## What was checked

A new unit test confirms the filter logic (NTFS kept, BitLocker and other filesystems excluded) against a synthetic
disk; two real loop-device tests build an actual NTFS partition with no `\Windows\System32` folder, confirm
automatic detection genuinely misses it, and confirm `lintab-windows-files enable --read-write --partition PATH`
correctly sets up that exact partition with its real `blkid` UUID. All 20 loop-device tests (dual-boot, shrink,
Remove LintabOS, and the two new ones) pass; the new window layout was verified by rendering it headlessly.
