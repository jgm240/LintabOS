# LintabOS 0.3.4 (pre-release)

Bug fix: a real user reported **LinWinMod stuck at "Looking for Windows..."** forever.

## The cause

`FilesPage._scan()` (and three similar background workers in the same window — `_open`, `_checked`, and the Registry
page's `_scan_hives`) ran their disk/hive discovery in a background thread with no exception handling. If that call
raised — disk enumeration has already failed with a real `DiskError` in this project's own test logs
(`lsblk: /dev/vda: not a block device`) — the thread died silently before reaching the `GLib.idle_add` call that updates
the label, leaving the page stuck on its initial "Looking for Windows…" / "Checking the drive…" / "Opening…" text forever.
Every other scanning window in this codebase (e.g. "Remove LintabOS") already guards against exactly this; this one didn't.

## The fix

All four background workers in LinWinMod now catch their own exceptions and show a plain-words message instead of
hanging. A new structural test parses `winmod_gui.py`'s own source and checks that every function calling
`GLib.idle_add` is wrapped in a `try`/`except`, so this bug class is caught if it's ever reintroduced.
