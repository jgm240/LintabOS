# LintabOS 0.3.3 (pre-release)

Addresses the reported "doesn't turn back on after the power button or closing the folio" problem, as far as it can be
addressed without a hand on the actual hardware.

- **Prefer deep sleep over s2idle.** Where the firmware offers real "deep" (S3) sleep, LintabOS selects it at every boot. This
  is the most common fix for "suspends, never wakes, needs a hard power-off" on this class of Intel hardware: s2idle depends
  on every driver's own resume code, where deep/S3 powers most of the system off and back on. Where the firmware only offers
  s2idle, this does nothing (there is nothing to switch to) — `lintab-sleep-mode status` says which.
- **Sleep & Power Button.** Choose what the power button and folio-close do: Suspend (the normal choice, with deep sleep
  preferred first), Lock the screen only (stays fully on — the choice that can't get stuck, if suspend still doesn't
  come back), or Do nothing. LintabOS's own `lintab-sleep-guard` service takes the power button and lid switch over directly,
  because GNOME's own power handling hardcodes "tablets always suspend" for the power button and has no setting for the lid
  switch at all (verified against `gnome-settings-daemon`'s own schema, not assumed).

## What was checked

22 new tests: the sleep-mode parsing and preference logic against every realistic `/sys/power/mem_sleep` format; power-button
and lid-switch device detection (a real bug — a device with only one handler wasn't found — was caught by a test and fixed
before this shipped); event classification; and the dispatch loop surviving a device it can't open.

## Not checked

A real power button or lid switch, and whether any of this actually fixes wake-up on the Duet 3 — that needs the tablet
itself. The Wi-Fi and fingerprint-login problems from 0.3.0 are unrelated and still open.
